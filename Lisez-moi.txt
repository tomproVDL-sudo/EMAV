EMAV - application pour téléphone et tablette (Android, iPhone), utilisable sans réseau
==================================================================================
Ce dossier contient UNIQUEMENT le code de l'application : aucun nom d'établissement,
aucune adresse, aucun plan, aucun chemin du réseau de la Ville, aucune visite.
Il peut donc être publié tel quel sur un hébergement https (dépôt GitHub avec GitHub
Pages, serveur de la Ville…). Une règle de sécurité intégrée à la page interdit tout
envoi de données vers un autre site.

Fichiers à publier : index.html, sw.js, manifest.webmanifest, icon-192.png, icon-512.png

Mettre à jour le dépôt GitHub (ou l'hébergement)
------------------------------------------------
1. Sur github.com, ouvrir le dépôt de l'application EMAV.
2. « Add file » > « Upload files » : glisser les 5 fichiers ci-dessus (pas ce Lisez-moi),
   puis « Commit changes ». Les fichiers du même nom sont remplacés. Les anciens fichiers
   qui ne servent plus (ex. dossier icones, plans_qai.json) peuvent être supprimés ;
   vérifier qu'aucun fichier de données (plans, établissements) n'est dans le dépôt.
3. La version (dans sw.js) change automatiquement à chaque nouvelle version : les
   téléphones prennent la mise à jour à la prochaine ouverture avec réseau (fermer puis
   rouvrir l'application). Les visites déjà saisies sont conservées.

Installation sur le téléphone (avec réseau, une fois)
-----------------------------------------------------
iPhone  : ouvrir l'adresse https dans Safari > bouton Partager > « Sur l'écran d'accueil ».
Android : ouvrir l'adresse dans Chrome > menu ⋮ > « Installer l'application ».
Puis dans EMAV : Réglages > nom et fonction ; accueil ou Réglages > « Importer
donnees_emav.json ».

Le fichier des données : donnees_emav.json
------------------------------------------
À créer sur l'ordinateur : EMAV > accueil > « Préparer un téléphone ». Il contient,
à jour de la base partagée, les établissements, les plans et les visites déjà faites
(dernière visite de chaque établissement, ou tout l'historique ; sans les photos).
Sur le téléphone, « Importer donnees_emav.json » charge tout en une fois : une
nouvelle visite y est préremplie et comparée à la précédente, même sans réseau.
À refaire avant une campagne pour avoir les dernières visites. Le fichier se transmet
en interne (messagerie de la Ville, câble USB, OneDrive pro) et ne se publie JAMAIS.
(Le donnees_emav.json du dossier QAI_CO2 ne contient que les établissements et les plans.)

Sur le terrain
--------------
Tout fonctionne en mode avion : visites, pièces, photos, fiches, export .zip.
Une nouvelle visite d'un établissement déjà évalué reprend les éléments de la visite
précédente (fenêtres, matériaux, ventilation, bouches, état constaté) à vérifier sur
place ; chaque pièce est comparée à la visite précédente (amélioration, dégradation,
sans changement).
Export PDF : les bibliothèques PDF sont gardées sur le téléphone au premier lancement
avec réseau.

Retour au bureau
----------------
Export .zip de la visite > l'envoyer sur l'ordinateur > EMAV sur l'ordinateur >
« Importer une visite (.zip) ». La visite rejoint alors la base EMAV du réseau (si la
base partagée est activée sur ce poste) et l'outil QAI CO2.

Attention
---------
- Ne pas désinstaller l'icône ni effacer les données de Safari/Chrome avant d'avoir
  exporté les visites : elles sont stockées dans le téléphone.
- Sur iPhone, si l'application n'est pas ouverte pendant plusieurs semaines, iOS peut
  vider ses données : exporter chaque visite après la tournée.
